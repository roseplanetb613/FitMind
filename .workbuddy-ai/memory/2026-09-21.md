## ⚠ 本仓 git 环境的一个坑（务必记住，已定位真因）

**症状**：commit 成功、reflog 也记了，但 `git log --oneline -1` 仍显示旧 HEAD，
新 commit 变 dangling（`git for-each-ref --points-at <sha>` 为空）。

**真因**：**ref 文件必须写完整 40 位 SHA**。我中途用缩写 `9f187dc` 写了一次，
git 直接报 `warning: ignoring broken ref refs/heads/feat/music-playback`
并判定为坏 ref —— 症状与"没写"极像，容易误判成外部进程在删 ref。
本仓 `refs/heads/feat/music-playback` 只存在于 `.git/packed-refs`，
`.git/refs/heads/` 下本来就没有对应 loose 文件，所以**第一次必须自己创建**。

⚠ 我先前在日志里断言"`git update-ref` 静默失败、有外部进程删 ref"是**错的**——
真因就是缩写 SHA 导致坏 ref。后续排查先看 `git rev-parse <branch>` 有没有
`ignoring broken ref` 警告，别再猜外部进程。

**正确写法**：

```bash
FULL=$(git rev-parse <short-sha>)          # 先取全 40 位
mkdir -p .git/refs/heads/feat
printf '%s\n' "$FULL" > .git/refs/heads/feat/music-playback
git rev-parse feat/music-playback          # 验证：应输出全 sha，无 warning
```

⚠ loose ref 会**覆盖** packed-refs 里的同名条目，写对了就生效。
建议优先用 `git update-ref`（它自己会写全 sha）；若用了它仍不生效，
再按上面手动写，并**务必用全 sha**。
